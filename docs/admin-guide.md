# 管理员使用指南

本文面向 AI 创作画布的管理员,按模块介绍如何用管理员账号完成日常管理与配置。文中的所有页面只有管理员登录后可见;普通用户看不到这些入口,直接访问也会得到 404。

> 适用场景:本地/LAN 独立模式(`run-local.sh`、`run-lan-local.sh`)。生产 Portal 模式下账号由 Portal 管理,本指南的账号管理部分不适用,但模型、凭据池、人像资产库、工作流库的配置方式相同。

## 0. 管理员账号从哪来

- **首次启动自动创建**:`run-local.sh` 首次启动时,终端会打印 `canvas-admin` 和 `canvas-user` 的一次性密码。用 `canvas-admin` 登录并按提示修改初始密码,这就是你的管理员账号。密码只打印这一次,忘了见 [2.3](#23-忘记本地测试密码怎么办)。
- **服务器上直接创建长期管理员**:在运行机器的终端执行:

```bash
PYTHONPATH=server .venv/bin/python -m ai_creation_canvas create-local-user \
  --data-dir .local-data --username admin --display-name "管理员" \
  --password 你的密码 --role admin
```

  创建后立即可用、无需改密、重启不丢。
- **自助注册出来的账号永远是普通用户**,不可能注册成管理员;管理员只能通过上面两种方式产生。

## 1. 登录与界面总览

1. 打开画布地址的 `/login`,用管理员账号密码登录。
2. 登录后,管理员在导航里比普通用户多 5 个入口(普通用户只有项目、资产、任务、统计):**账号管理、模型派发、工作流库、人像资产库、使用统计**。

一句话理解管理员的工作:**管账号 → 配模型与 Key → 派发 → 看用量**,外加人像资产库与工作流库两个可选功能。

## 2. 账号管理

入口:导航「账号管理」。

### 2.1 待审核注册(审核新用户)

有人自助注册后,账号先进入"待审核"状态,此时:

- 注册人登录会得到和密码错误一样的提示,进不了系统;
- 「账号管理」页面顶部会出现「待审核注册」区,显示显示名、用户名和申请时间;
- 点**通过**:账号立即生效,可以登录;点**拒绝**:这条注册被删除(含密码),操作会记入审计日志。

**注意:通过只代表"允许登录",不代表"能用模型"。** 通过之后还要到「模型派发」给这个人分配模型(见第 3 章)。

### 2.2 账号列表(启用 / 停用 / 设置密码)

- 列表显示每个账号的显示名、用户名、角色(管理员/普通用户)、已分配模型数量,以及「已启用/已停用」状态;
- **停用**:该账号立即退出登录、无法再登录,已有数据保留;再点**启用**即恢复;
- **设置密码**:普通用户行的「设置密码」可为该用户设定新密码。新密码立即生效、该账号现有登录会立即失效;勾选「下次登录需改密」后,对方下次登录会被要求先改一次密码。该操作会记入审计日志。
- 管理员自己的行上是「修改密码」,需要输入当前密码(等价于侧边栏左下角的「修改密码」入口,所有用户都有);
- 管理员**不能**给其他管理员设置密码(与其他管理员账号一样不显示该按钮),也不能在页面上新建账号(见第 0 章两种建号方式)。

### 2.3 忘记本地测试密码怎么办

管理员忘记自己密码时(管理员不能互相改密,只能走这里),停止服务后在运行机器的终端重置(命令只显示一次新密码,该账号下次登录会被要求再次改密):

```bash
PYTHONPATH=server .venv/bin/python -m ai_creation_canvas reset-local-password \
  --data-dir .local-data --username 账号名
```

## 3. 模型与调用线路(核心页面)

入口:导航「模型派发」(页面标题「模型与调用线路」)。这是管理员最重要的页面,从上到下依次是:**导入凭据池 → 逻辑模型 → 调用设置 → 用户模型派发**。

> 记住一条边界:普通用户只选择"逻辑模型";供应商、线路和凭据池(Key)全部由管理员在这个页面隔离管理,普通用户看不到也改不了。

### 3.1 导入凭据池 JSON(管 Key)

真实模型需要供应商 API Key。Key 永远不放进代码,而是放在一个 JSON 文件里,由你在页面上导入:

1. 复制模板 `server/config/credential-pools.example.json`,放到仓库外、只自己可读的位置(`chmod 600`),把占位值换成真实 Key;
2. 页面上「导入凭据池 JSON」区:点「选择凭据 JSON」选文件 → 勾选"确认替换现有凭据池;新任务使用新配置,已提交任务不会重放。" → 点「导入并替换凭据池」;
3. 成功后显示「已导入 N 个凭据池。」,页面只显示池 ID、供应商、分组、Key 数量和并发摘要,**不会显示 Key 本身**。

要点:

- 不同供应商互不借 Key:Banan、GPT-Image2、Seedream、Seedance 各用各的池,池里的 `provider`/`group`/`family` 必须与系统要求的四元组一致(见 README 对照表);
- 每把 Key 的 `max_concurrency` 是并发上限(1–32),按你购买的套餐并发填写;
- 换 Key = 再导入一次新 JSON,新任务立即用新 Key,**无需重启**;
- **轮换后先别删旧 Key**:进行中的任务还记着原 Key,删了会失败;等任务全部结束后再换。

### 3.2 逻辑模型(用户能看到的模型)

左侧「逻辑模型」列表 + 「新建」按钮。新建/编辑时填写:

- **模型 ID**:创建后不可改,建议用稳定命名;
- **模型显示名**:用户在选择模型时看到的名字;
- **能力模板**:「多参生图」或「多参生视频」;
- **模型类型**:Seedream(Ark 官方)/ Seedance(Ark 官方)/ Banana(Chiyun)/ GPT-Image2(Chiyun),决定它走哪家供应商的调用协议。

每个模型还支持生命周期操作:**启用 / 停用 / 归档 / 恢复 / 删除 / 清理历史运行配置**。删除和清理需要输入模型显示名确认;仍被任务、派发或线路引用的对象不会被直接删除,系统会提示引用数量。

### 3.3 调用设置(给模型接上线路和 Key 池)

选中一个模型后,「调用设置」区按调用方式(Ark 官方 / Chiyun)各显示一张卡片:

- 勾选「启用」;
- 从下拉框选择**兼容的凭据池**(只有四元组精确匹配的池才会出现在选项里);
- 可调整**优先级**和**最大并发**;
- 点「保存 <方式> 设置」。

注意:调用协议(地址、模型名、参数合同)由系统内置维护,你只能调整池、优先级、并发和启用状态——这是有意的安全边界,不能通过页面引入任意地址或脚本。若提示"尚未配置与此调用方式精确匹配的凭据池",先回到 3.1 检查池的四元组。

页面底部的「历史审计记录」是可折叠的只读列表,归档、重复或清理过的线路只在这里留痕。

### 3.4 用户模型派发(决定谁能用什么)

页面底部「用户模型派发」区:

1. 在「选择账号」下拉框选一个用户;
2. 勾选要给他用的模型(图片、视频分别勾);
3. 点「保存派发」,看到「派发已保存」即成功。

派发后,该用户登录画布就能选择这些模型;没派发的模型他看不到也调不了。撤权 = 去掉勾选再保存一次。

### 3.5 模型能跑起来的三个条件

1. 逻辑模型已启用;
2. 至少一条线路(调用设置)已启用;
3. 对应凭据池里至少有一把 Key(生产环境还需要 Redis 可用)。

页面提示"无健康线路"时,按这三条排查。

## 4. 人像资产库(可选)

入口:导航「人像资产库」。只有要使用"上传虚拟人图片 → 生成视频"工作流时才需要配置。

1. 准备公司级凭据:火山方舟 OpenAPI 的 AK/SK + TOS 对象存储的 AK/SK、桶名、区域、项目名;
2. 按 `server/config/asset-library.example.json` 的格式写好 JSON(字段就这 8 个,别多加);
3. 页面「导入资产库 JSON」区:选「选择配置 JSON」文件 → 勾选「确认覆盖服务端配置」→ 点「导入」;
4. 导入后立即生效,无需重启。

- 「服务状态」区只显示摘要:服务是否启用、方舟 AK/SK 与 TOS 是否已配置、存储桶、区域、项目名、默认分组——**密钥永不回显**;
- 「AIGC 分组」列出方舟侧的分组;尚未创建时,首次上传人像会自动创建默认分组;
- **未配置时**,用户上传人像会得到 503 提示,系统不会偷偷改用别的图床;
- 用户上传的人像进入方舟私域资产库,审核通过后,Seedance 视频任务以 `asset://<id>` 引用;
- 方舟控制台发的 SK 如果是 base64 编码,导入时自动解码,不用手工处理。

## 5. 工作流库(ComfyUI,可选)

入口:导航「工作流库」。用于把 ComfyUI 工作流模板提供给用户。

前置条件:服务器启动时已通过 `AICC_COMFYUI_SERVICES`(本地)或 `--comfyui-services`(生产)指定 ComfyUI 服务声明文件;这是服务器上的配置,不在页面里。

页面操作:

1. **导入工作流**:选「选择工作流 JSON」文件、填「工作流显示名」和「ComfyUI 服务 ID」,点「导入工作流」。系统会做安全过滤(带控制 URL、密钥、脚本的字段会被拒绝),导入成功后工作流**默认处于停用状态**;
2. **模板列表**选中一个工作流后,右侧详情面板可:
   - 查看格式、校验和、**依赖状态**(哪些节点是核心节点、哪些需确认)与只读预览;
   - **启用 / 停用 / 归档 / 恢复**;
   - **导出**:「下载 <格式> JSON」;
3. **账号派发**:在「账号派发」区勾选要开放给哪些用户,点「保存派发」。只有已派发且启用的工作流才会出现在普通用户的可用模板里。

## 6. 使用统计(只读)

入口:导航「使用统计」。

- 顶部 6 张卡片:全部任务、成功、进行中、失败、图像、视频;
- 下方按用户的表格:每个账号的任务数、图像数、视频数、成功/进行中/失败;
- 统计按服务端确认的用户 ID 汇总,普通用户看不到别人的数据;
- 本页**只读**,没有任何可修改的设置。

## 7. 常见问题速查

| 现象 | 处理 |
| --- | --- |
| 注册后用户说登录不上 | 去「账号管理 → 待审核注册」通过,再在「模型派发」给他派模型 |
| 提示"凭据导入未配置" | 服务器启动命令缺 `--credential-pools` / `--credential-pools-root` 参数(生产) |
| 导入 JSON 被拒绝 | 检查扩展名、UTF-8 编码、字段名拼写、Provider/分组/模型族对应、`max_concurrency` 1–32 |
| 模型无健康线路 | 模型与线路都要启用、池里有 Key、生产环境 Redis 可用(见 3.5) |
| 任务显示 `submission_unknown` | 不要换 Key 重提,用原任务查询,避免重复扣费 |
| 人像上传报 503 | 未配置人像资产库 JSON,去「人像资产库」导入 |
| 管理员密码丢了 | 停服务后跑 `reset-local-password`(见 2.3) |

## 8. 安全注意事项

- **Key 只存在于你本地的 JSON 文件和服务端**;浏览器永远看不到、也存不了 Key;
- 不要把凭据 JSON 提交到 Git,也不要在聊天、截图里发 Key;
- 停用账号会立刻踢下线;审核操作(通过/拒绝)都会写审计日志;
- 局域网入口只建议在可信局域网内使用;不要把它暴露到公网。
