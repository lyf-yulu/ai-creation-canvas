# 简化模型调用设置设计

## 目标

管理员只声明用户可见的逻辑模型，并为模型启用预置调用方式。普通用户只选择模型，不接触 Provider、API Key、模型族、适配器或调用协议。

本切片的可见成功条件：管理员能用少量选择完成调用设置；普通用户提交 Banana 任务后，服务端自动选择可用调用方式，画布显示并可下载真实结果。

## 产品模型

首批逻辑模型固定为：

- Banana：支持 Chiyun、T8Star。
- GPT-Image2：支持 Chiyun。
- Seedream：支持 Ark 官方。
- Seedance：支持 Ark 官方。

“调用方式”是仓库内受信模板，不是管理员自由创建的协议对象。模板在代码中固定 Provider、模型族、适配器、供应商参数映射和能力合同。

管理员在模型的“调用设置”中只管理：

- 是否启用某个预置调用方式；
- 绑定哪个兼容凭据池；
- 优先级；
- 最大并发。

凭据池继续隔离 Key 与分组。浏览器只能看到池 ID、分组、可用数量和忙碌数量，不能读取或提交真实 Key。

## 路由规则

服务端按优先级选择启用且有容量的调用方式；同一方式内只轮询与该模型、Provider 和分组精确兼容的 Key。

- 限流、超时、网络故障、供应商 5xx：允许切换到下一把 Key或下一调用方式。
- 内容审核、参数错误、鉴权失败及其他业务 4xx：停止任务，不跨调用方式重试，避免重复付费。
- 已获得供应商任务 ID 或结果但本地状态不明确：标记未知，不重新提交。
- 幂等键、用户 ID、最终命中的调用方式和 Key 指纹继续写入服务端任务记录；不记录原始 Key。

## 管理界面

逻辑模型列表保留创建、编辑显示名、介绍、启停和派发。模型创建时只选择四种受信模型类型之一。

删除自由编辑的线路表单。模型详情改为“调用设置”卡片，每种受信调用方式一张卡：启用开关、凭据池、优先级、最大并发和只读健康状态。无兼容凭据池时不能启用，并显示直接原因。

## 结果闭环

9003 离线验收必须返回可被浏览器真实解码的 PNG/MP4，不再使用只有文件头的伪媒体。浏览器验收检查任务成功、结果节点连线、图片自然尺寸大于零、HEAD/Range/完整下载和用户归属隔离。

真实付费验收在离线门禁通过后单独执行。Key 只由服务端进程临时读取，浏览器、日志、Git 和测试报告均不得获得；先每条代表调用方式运行一次，再在明确预算内扩大到批量样本。真实调用失败不自动无限重试。

## 本轮边界

本轮不开放管理员自定义 Provider URL、适配器、参数合同或远程代码；不把真实 Key 写入应用数据库；不新增通用插件系统。新供应商必须先在代码中增加受信调用模板和合同测试，之后才会出现在“调用设置”中。
