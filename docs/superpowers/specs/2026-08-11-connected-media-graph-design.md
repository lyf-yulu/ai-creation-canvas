# 可编辑互联媒体画布设计

## 1. 目标

把当前只能拖动和直接提交任务的画布，升级为可编辑、可连接、可复用的媒体工作流画布。用户通过三类主节点完成创作：输入节点、模型调用节点、结果保存节点；后续再以同一接口增加 Skill 再处理节点。

本设计必须实现：

- 节点创建、编辑、删除、批量删除和连线管理；
- 空白可编辑提示词节点与本地 TXT 导入；
- 有序图片、视频、音频素材集合，拖拽排序会改变 `@图片1`、`@视频1`、`@音频1` 的语义；
- 模型节点通过命名端口接收输入，提示词端口最多一条连线；
- 图片与视频模型的端口、参数和限制由服务端模型声明驱动；
- UI 中显示并允许修改的参数必须进入同源任务请求，并由服务端适配器真实映射到官方 API 请求；
- 结果节点支持预览、下载、删除、再次连接到其他模型节点；
- 刷新恢复、失败重试、任务输入快照、双用户隔离和受控真实调用。

## 2. 非目标

本轮不实现提示词优化、视频超分、ComfyUI、热门 Skill 执行或远程插件。只定义 `processor` 节点扩展边界，后续按独立切片接入。普通用户不能增加动态模型脚本、自定义服务地址或浏览器 Key。

## 3. 架构选择

采用“有序集合输入节点 + 带命名端口的模型调用节点 + 结果保存节点”。不采用每个素材一个节点，因为 15–30 个参考素材会使画布失控；不把上传功能塞入模型节点，因为这会混合输入管理、任务调用和结果保存职责。

```text
提示词节点 ─────────────────────→ prompt（最多 1 个）
图片集合/图片结果 ──────────────→ reference_images
图片集合/图片结果 ──────────────→ first_frame
图片集合/图片结果 ──────────────→ last_frame
音频集合/音频结果 ──────────────→ reference_audio
视频集合/视频结果 ──────────────→ reference_video
                                      │
                                  模型调用节点
                                      │
                                      ▼
                                  结果保存节点
```

模型不支持的端口不显示；输入组合互斥时，连线阶段和提交阶段都要阻止，并显示具体原因。

## 4. 节点模型

### 4.1 通用字段

每个节点继续使用画布现有的稳定 ID、位置、宽高和元数据。新增语义字段必须可 JSON 序列化并通过项目 API 持久化。浏览器存储和服务端项目文档都不得包含 API Key、上游临时 URL 或本地绝对路径。

所有节点统一支持：

- 单选、多选、拖动；
- `Delete` / `Backspace` 删除；输入控件正在编辑时不响应删除快捷键；
- 节点右上角菜单删除；
- 批量删除；
- 删除节点时自动清理所有关联连线；
- 删除结果节点默认只删除画布引用，资产库原文件需单独确认；
- 400 ms 项目保存防抖和失败后重试。

### 4.2 提示词节点

创建后显示空白多行编辑器，不触发任务、不显示加载动画。用户可直接输入，也可选择本地 `.txt` 文件读取为 UTF-8 文本；文件必须是普通文件，最大 1 MiB，包含非法 UTF-8 或超限时拒绝且保留原文本。导入后文本仍可编辑。

提示词节点提供一个 `prompt` 输出端口。每个模型节点的 `prompt` 输入端口最多连接一个提示词节点；一个提示词节点可以连接多个模型节点。

### 4.3 有序素材集合节点

集合节点类型为图片、视频或音频，每个条目保存：

- 用户私有 `asset_id`；
- 原始文件名的安全显示值；
- MIME、字节数和可选媒体尺寸/时长；
- 稳定条目 ID；
- 当前排序位置。

节点内部支持上传、预览、重命名显示标题、移除和拖拽排序。排序后的显示编号从 1 开始即时重算：`@图片1`、`@图片2`、`@视频1`、`@音频1`。提示词中的编号按任务提交瞬间的集合顺序解析；任务创建后保存不可变输入快照，之后继续排序不会改变已提交任务。

集合节点自身不按某个模型限制素材数量。连接模型节点后，模型节点根据声明显示“已使用 / 最大数量”，提交前校验 MIME、大小、像素、时长、数量和组合规则。

### 4.4 模型调用节点

模型节点包含管理员派发的模型选择、命名输入端口、动态参数控件、输入摘要、运行/取消/重试按钮和任务状态。节点只显示用户有权使用且支持当前调用类别的模型。

端口角色至少包括：

- `prompt`
- `reference_images`
- `first_frame`
- `last_frame`
- `reference_video`
- `reference_audio`
- 后续声明允许的扩展角色

连线保存来源节点、目标节点和目标端口。相同来源可连接不同角色，但模型声明的互斥规则必须生效。模型节点不内嵌长期媒体副本，只读取连接的输入节点或结果节点。

### 4.5 结果保存节点

结果节点保存同源受控结果地址、媒体类型、任务 ID、模型 ID、参数快照、创建时间和状态。图片、视频、音频分别用原生预览控件；视频使用 `preload=metadata` 并由同源结果接口支持 GET、HEAD、Range。

结果节点提供：

- 下载按钮，使用服务端提供的安全文件名和 `Content-Disposition`；
- 删除画布节点；
- 明确选择后删除资产库原文件；
- 作为图片、视频或音频输入重新连接到模型节点；
- 多结果任务为每个成功媒体创建独立结果节点，并保留同一来源任务关系。

## 5. 连接与执行语义

连接是有方向、有目标端口的关系：

```json
{
  "id": "connection-id",
  "fromNodeId": "image-collection-a",
  "toNodeId": "video-model-b",
  "toPort": "reference_images"
}
```

连接创建时校验节点媒体类型与端口类型。删除连接不删除节点或资产。模型节点运行时执行以下步骤：

1. 读取当前项目中指向该模型节点的连线；
2. 确认恰好一个有效提示词输入；
3. 按端口读取素材集合及结果节点；
4. 按集合顺序生成稳定的输入快照和 `@媒体N` 映射；
5. 对模型声明执行参数、数量、MIME、大小、时长和互斥组合校验；
6. 用参数控件白名单重建 `params`，忽略任何未声明字段；
7. 上传或登记本地素材，获得当前用户拥有的 `asset_id`；
8. 通过同源 `/api/v1/jobs` 提交；
9. 保存任务与项目、源模型节点和输入快照的关系；
10. 轮询或恢复任务，成功后创建结果节点。

## 6. 模型能力声明

模型能力必须为受控数据，不能包含 Key、URL、脚本、插件、请求头或浏览器执行代码。建议声明结构包含：

```ts
type ModelCapability = {
  model_id: string;
  service_id: string;
  display_name: string;
  operations: string[];
  inputs: {
    prompt: { required: true; max_characters?: number };
    image?: { roles: string[]; max_count: number; accepted_mime_types: string[]; max_bytes?: number };
    video?: { roles: string[]; max_count: number; accepted_mime_types: string[]; max_bytes?: number; max_duration_seconds?: number };
    audio?: { roles: string[]; max_count: number; accepted_mime_types: string[]; max_bytes?: number; max_duration_seconds?: number; may_be_only_input: boolean };
  };
  parameter_schema: Record<string, unknown>;
  constraints: Record<string, unknown>;
  result: { media_types: string[]; requires_immediate_server_copy: true };
};
```

参数控件由安全 JSON Schema 子集生成，支持字符串、布尔值、有限数字、整数、枚举、默认值、范围、条件显示和条件必填。每个显示参数必须满足四项合同：

1. UI 修改后写入模型节点项目文档；
2. 运行时进入 `/api/v1/jobs` 的 `params`；
3. 服务端按模型声明再次校验；
4. Ark 或其他适配器把该值映射到官方请求体或明确的官方提示词参数。

如果某个字段无法完成第 4 项，它不能出现在 UI。合同测试必须捕获“控件存在但未真实上传”的假实现。

## 7. 官方能力映射

### 7.1 Seedream

图片模型按实际版本声明以下能力：文本生成图片、单图或多图参考、图片编辑、组图、尺寸、提示词优化、输出格式、响应格式、组图数量、流式结果、水印和管理员显式开启的工具。

- Seedream 4.0 / 4.5 / 5.0 lite 最多 14 张参考图；
- Seedream 5.0 pro 最多 10 张参考图；
- 支持的输入格式包括 JPEG、PNG、WebP、BMP、TIFF、GIF、HEIC、HEIF；
- 单张最大 30 MiB、最大 6000×6000、宽高比 1/16 至 16；
- 组图要同时校验参考图数量与输出数量；
- 当前官方图片生成参数表未声明 `seed`，因此这些声明不显示 seed 控件。

官方依据：[图片生成 API](https://docs.volcengine.com/docs/82379/1541523)、[Seedream 教程](https://docs.volcengine.com/docs/82379/1824121)。

### 7.2 Seedance

视频模型按版本声明文本生成视频、首帧、首尾帧、多模态参考、视频编辑、延长、比例、分辨率、时长、生成音频、输出格式、返回尾帧、水印、固定相机、草稿模式和管理员显式开启的工具。

- Seedance 2.0 最多 9 图、3 视频、3 音频，不能只用音频；
- Seedance 2.5 最多 30 图、10 视频、10 音频，并允许仅音频输入；
- 首帧/首尾帧模式与多模态参考模式不能非法混用；
- `seed=-1` 仅在官方确认支持的 1.0/1.5 声明中出现；2.0/2.5 当前声明不显示 seed；
- `safety_identifier` 由服务端基于用户 ID 生成不可逆稳定值，不由用户编辑；
- `priority` 等运维字段默认不向普通用户开放；
- 上游临时结果成功后立即转存，浏览器不直接重复下载上游地址。

官方依据：[创建视频任务 API](https://docs.volcengine.com/docs/82379/1520757)、[查询任务 API](https://docs.volcengine.com/docs/82379/1521309)、[取消任务 API](https://docs.volcengine.com/docs/82379/1521720)、[Seedance 2.5 说明](https://docs.volcengine.com/docs/82379/2607688)。

## 8. 服务端素材与安全边界

上传经同源认证、CSRF、用户归属、MIME 嗅探、扩展名、大小和媒体元数据校验后写入受限临时文件，再原子转入用户私有资产库。浏览器对象 URL 只能用于提交前本地预览，不能进入项目文档或模型请求。

Ark 图片 API需要 URL 或 Base64；服务端负责将当前用户资产转换为短时、最小权限的可访问表示。视频 API 的图片、视频、音频按 `content` 和 `role` 映射。普通上传图片不能伪装为官方 `asset://` 虚拟人资产；真人或虚拟人素材必须遵循官方认证、授权和资产归属流程。

下载必须通过同源、登录、任务归属和资产归属检查。响应采用安全文件名、`nosniff`、私有缓存策略和 Range；不回显上游地址。

## 9. 错误处理

编辑和连线错误在本地显示具体可操作说明。提交失败保留节点、连线、参数和输入快照，不自动重复付费提交。上游错误转换为受控错误码和用户友好信息，不返回原始响应、Key、Cookie、完整 URL 或内部路径。

任务状态覆盖 submitting、queued、running、succeeded、failed、expired、cancelled。取消只调用一次上游取消接口；未知结果先按原幂等键查询或恢复，不创建重复任务。

## 10. 增量实施顺序

1. 画布基础编辑：提示词编辑、TXT 导入、节点删除、命名端口、连线创建/删除、结果下载。
2. 有序素材集合：图片、视频、音频上传、预览、移除、拖拽排序和编号。
3. 图片模型闭环：动态参数、多参考图图生图、图片编辑、组图多结果。
4. 视频模型闭环：首帧、尾帧、多参考图、参考视频、参考音频、动态视频参数、取消任务。
5. 稳定性收口：刷新恢复、失败重试、输入快照、双用户隔离、响应式布局和真实最小付费调用。

每个切片必须可独立启动和验收，不把全部功能一次性合并后再排错。

## 11. 测试与验收

### 11.1 前端

- 提示词节点初始为空、可编辑、可导入 TXT，编辑不触发任务；
- 节点菜单、快捷键、多选删除及关联连线清理；
- 命名端口类型、一个提示词限制和连接互斥；
- 集合上传、移除、拖拽排序、编号更新和提交快照；
- 参数默认值、类型、范围、条件显示、持久化和安全白名单；
- UI 参数修改后，真实 `/api/v1/jobs` 请求体包含准确值；
- 图片、视频、音频结果预览、下载和再次连接；
- 刷新后节点、连线、参数、集合顺序和待处理任务恢复；
- 桌面、415 px、240 px 下画布、节点编辑、参数面板和任务托盘可操作且不遮挡。

### 11.2 服务端

- 上传的认证、CSRF、MIME、大小、归属、原子写入和取消清理；
- 资产和结果的跨用户 404/403 边界、GET/HEAD/Range 和安全响应头；
- 模型能力声明严格解析，危险字段拒绝；
- 每个公开参数的“模型声明 → JobRequest → 适配器官方字段”合同测试；
- 输入数量、角色、互斥模式和模型版本差异；
- 多结果、部分成功、失败、过期、取消和幂等恢复；
- 项目保存冲突与同一任务只回填一次。

### 11.3 真实验证

模拟合同全部通过后才使用付费服务。每个代表模型只提交一次最小任务，验证：

- Seedream 多参考图输入、至少一个非默认参数真实到达请求并影响请求体；
- Seedance 参考素材组合、至少两个非默认参数真实到达请求并进入官方任务；
- 结果转存、下载、Range 播放和刷新恢复；
- 管理员与普通用户模型派发、项目归属和资产隔离；
- 浏览器控制台无未处理错误，浏览器存储无 Key 和上游临时 URL。

真实验证日志只保留在 Git 忽略的测试目录，记录时间、模型、状态、短任务 ID、耗时和安全错误码，不记录提示词、Key、Cookie、媒体内容、上游 URL 或原始请求响应。

## 12. 完成定义

只有当输入节点可编辑、素材集合可排序、命名端口可连接、参数真实提交、结果可预览下载并可再次连接，且全量自动化、真实浏览器、双用户隔离和代表模型真实调用通过后，本功能才可标记完成。仅完成视觉控件或模拟请求不算完成。
