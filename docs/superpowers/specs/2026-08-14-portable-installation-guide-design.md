# 可迁移安装指南设计

日期：2026-08-14  
状态：已确认；增加管理员 JSON 凭据导入后再实现安装文档

## 目标

让首次拉取仓库的维护者不依赖原开发机器、既有测试数据或相邻 Portal 源码，按照文档即可完成离线体验、真实模型配置和正式发布包部署。所有步骤必须使用仓库当前公开入口，并明确哪些配置可复制、哪些数据和凭据必须由部署者自行创建。

## 文档结构

采用两层入口：

1. 根目录 `README.md` 负责项目能力、系统要求、五分钟离线启动、文档导航和安全警告。
2. `docs/installation.md` 提供完整迁移流程，包括源码安装、发布包安装、账号初始化、凭据池、Redis、服务启动、验证、备份、升级和排障。

`docs/operations.md` 保留详细运维语义；安装指南只引用其中需要持续维护的高级内容，不复制全部设计历史。

## 支持的安装路径

### 离线体验

- Python 3.12、Node/npm 和 Git。
- 创建 `.venv`，按锁文件安装 Python 与前端依赖。
- 使用 `scripts/run-local.sh` 构建并启动 `127.0.0.1:8992`。
- 首次账号、改密、重置密码和数据目录位置必须写清楚。
- 明确离线演示不会调用模型，也不会产生费用。

### 可迁移发布包

- 使用 `scripts/build-release.sh` 生成不包含 Node、Key、数据库和媒体的发布目录。
- 目标机器只安装 Python 3.12 依赖，验证 `manifest.sha256` 后启动。
- 数据目录、配置目录、Redis 和反向代理均位于发布包之外，从而可以替换发布包而不迁移运行状态。

### 真实模型

- 普通使用者只选择逻辑模型，不接触供应商、线路或 Key。
- 管理员可以从后台选择严格 JSON 凭据池文件上传；服务端将其写入仓库外、权限为 `0600` 的受控配置路径。
- 当前受信模型为 Banana、GPT-Image2、Seedream、Seedance；不得提供浏览器内粘贴、逐项编辑或回显 Base URL/Key 的表单，唯一例外是管理员显式选择本地 JSON 后的一次性原样上传。
- 生产受管线路要求 Redis 和独立的 `AICC_CREDENTIAL_HMAC_KEY`。
- 文档只给变量名、占位符和文件格式，不给真实凭据。

## 管理员 JSON 凭据导入

本阶段采用最小可部署的后台文件导入，不实现浏览器内逐项编辑 Key。

- 管理员页面提供 `.json` 文件选择和明确的“导入并替换凭据池”动作；选择文件本身不自动提交。
- 前端不调用 `File.text()`，不解析或渲染文件内容，不写入 React 全局状态、IndexedDB、localStorage、日志或错误监控；只用 `FormData` 把原始文件发送到同源管理 API，完成后清空文件输入。
- API 必须在读取 multipart body 前完成管理员身份隐藏，提交时验证 CSRF。普通用户、未登录用户和跨用户请求统一不能探测接口或配置状态。
- 文件上限 1 MiB，只接受 UTF-8 JSON；拒绝重复字段、未知字段、空池、重复 Key ID、越界并发和不受信 Provider/group/family 组合。服务端配置目标及其父目录不得经过符号链接。
- JSON 只允许 `version`、`pools`、`provider`、`group`、`allowed_families`、`keys`、`id`、`api_key` 和 `max_concurrency`。不得包含 Base URL、模型名、适配器、参数映射、远程脚本、请求头或浏览器代码。
- 服务端在受控目录创建权限为 `0600` 的临时文件，写入并 `fsync`，使用正式 `CredentialPoolLoader` 完整验证后才原子替换目标文件并同步目录。验证、写入或重载失败时保留上一份文件和 last-known-good 内存快照。
- 成功响应只返回安全摘要：池 ID、Provider、分组、允许模型族、Key 数量、总并发和 revision digest；不得返回 Key、文件内容、绝对路径或可推断 Key 的指纹。
- 新任务从下一次线路选择开始使用新快照；已经进入提交或已提交的任务继续使用原不可变路由快照，不能因换 Key 自动重放。
- 部署必须显式配置可写的 `--credential-pools` 和 `--credential-pools-root`。未配置目标路径、目标位于仓库内、权限不安全或生产环境不是 HTTPS/受信反向代理时，后台导入保持不可用并显示安全原因。

调用协议、受信 Origin、Provider 模型名和参数合同继续由发布版本维护；“导入 Key”不等于允许管理员导入任意调用代码。这是当前紧工期下避免 SSRF、Key 外送和不可审计动态协议的必要边界。

## 迁移与持久化边界

- 必须备份 SQLite 数据目录、资产和本地结果目录；不得复制会话、临时验收目录或构建缓存作为发布包内容。
- 升级采用“备份数据与配置 → 构建新发布目录 → 校验清单 → 停止旧进程 → 使用原数据/配置启动新发布目录 → 登录和结果下载验证”。
- 回滚只切回上一发布包和匹配配置，不回滚或手工删除 SQLite。
- 多进程生产部署必须使用共享 Redis；当前本地上传信号量和 provider submission budget 不能被描述成跨副本全局队列。

## 可复制性与验证

- 文档命令从全新路径执行，不依赖绝对开发机路径。
- 所有命令使用仓库实际 CLI 参数；提供 `--check-config`、登录页、模型目录、上传、任务和结果下载的验证清单。
- README 与安装指南中的命令由文档测试或 Shell 语法/入口帮助检查保护；JSON 示例由后端正式 schema 测试加载。
- 发布前运行 Python、前端、类型、构建、Chromium、安全扫描、依赖审计和差异检查。

## 非目标

- 不承诺一条命令自动配置生产域名、TLS、Portal、Redis 或供应商账号。
- 不把本机 9003 验收账号、真实媒体、成本证据或真实 Key 做成默认安装数据。
- 不提供任意 Provider URL、远程插件或浏览器端 Key 管理。
