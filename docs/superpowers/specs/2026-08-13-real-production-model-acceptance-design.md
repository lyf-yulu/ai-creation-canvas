# 无限画布真实生产模型接入与验收设计

状态：等待用户审阅书面设计

日期：2026-08-13

## 1. 目标与边界

本阶段把 `ai-creation-canvas` 的无限画布连接到真实供应商生产 API，并以普通用户在正式前端发布产物中的完整操作证明四个逻辑模型可用：Banana、GPT-Image2、Seedream、Seedance。

验收实例运行在本仓库隔离的 `127.0.0.1:9003` 和专用数据目录。不得修改、重启、读取状态或依赖 `/Users/260413a/ai-generation-portable-apps` 的既有生产服务。隔壁应用仅用于只读研究非敏感代码、测试和协议文档；本仓库运行时保持独立。

## 2. 模型与受信渠道

| 逻辑模型 | 真实渠道 | 固定生产 Origin | 调用协议 | 凭据池隔离 |
| --- | --- | --- | --- | --- |
| Banana | Chiyun | `https://chiyun.work` | Gemini `generateContent` | `chiyun / banana` |
| GPT-Image2 | Chiyun | `https://chiyun.work` | OpenAI Images `POST /v1/images/edits` | `chiyun / gpt-image2` |
| Seedream | Ark 官方 | `https://ark.cn-beijing.volces.com` | Ark Image API | `ark / seedream` |
| Seedance | Ark 官方 | `https://ark.cn-beijing.volces.com` | Ark Content Generation API | `ark / seedance` |

Origin、供应商模型名、适配器类型、参数映射和输入输出合同均由服务端代码拥有。管理员只能选择凭据池、启用状态、优先级和最大并发，不能通过浏览器或管理 API 改写内部调用协议。

四个凭据池相互隔离。任何 Key 不得跨供应商、分组或模型族轮询。没有通过真实验收的线路保持禁用。

## 3. 正式运行形态

9003 必须使用本仓库正式静态构建产物和正式 Python 服务入口，不加载演示适配器、MockTransport、测试供应商或伪媒体结果。测试数据、结果和凭据配置全部放在 Git 忽略的隔离目录。

真实 Key 只进入权限为 `0600` 的服务端凭据文件或服务端进程环境。Key 不得出现在浏览器响应、日志、错误、数据库公共投影、Git 差异、测试报告或进程命令行中。用户已在对话中提供的 Key 在验收后应由管理员轮换。

并发和租约沿用正式模型路由架构。单实例验收仍必须保留幂等键、任务归属和提交状态机；正式多实例部署继续使用 Redis 协调，不以浏览器状态代替服务端所有权。

## 4. 真实生产验收矩阵

本轮执行十二个真实供应商任务，硬上限为十二次新的 provider submission。该上限用于阻止程序错误造成无限重复提交，不是费用限制。

### Banana

1. 单参考图生成。
2. 多参考图生成。
3. 调换参考图顺序后生成，证明 `@图片1`、`@图片2` 的顺序真实传递。

### GPT-Image2

1. 单参考图编辑。
2. 多参考图编辑。
3. 使用另一项受声明支持的尺寸参数生成。

### Seedream

1. 单参考图编辑。
2. 多参考图编辑。
3. 使用另一项受声明支持的输出参数生成。

### Seedance

1. 文生视频。
2. 首帧图生视频。
3. 多参考图视频。

每项使用新的项目、任务或可追踪节点身份和新的幂等键。业务 4xx 不切换线路；可能已经送达供应商但结果不明确的提交进入 `submission_unknown`，不得自动重放。明确未送达的临时错误只能按既有状态机和剩余提交预算处理。

## 5. 成功判定

单个任务必须同时满足以下条件才算通过：

1. 普通用户从无限画布上传输入、连接命名端口并提交真实任务。
2. 请求使用声明中的真实供应商、真实模型、真实参数和有序输入。
3. 供应商结果被服务端下载到本地私有结果目录，不依赖长期外链。
4. 图片可以真实解码，宽高大于零；视频具有受支持的 MIME、有效容器签名并能完整读取。
5. 结果 API 的 GET、HEAD、单 Range 和完整下载均通过。
6. 画布生成结果节点，并建立模型输出到结果节点的连接；任务状态离开排队或运行态进入成功终态。
7. 结果、任务、资产和项目均归属普通用户；管理员和另一普通用户不能读取普通用户私有对象。
8. 数据库中的任务、用量和线路快照带正确 `userId`；管理员统计页面可看到对应聚合记录。
9. 重复相同幂等请求不会产生第二次供应商提交。
10. 输出文件、尺寸、MIME、字节数、任务 ID 和脱敏状态进入验收报告；报告不得包含 Key、完整提示词或供应商原始敏感响应。

任何一个逻辑模型没有至少三个真实落盘结果，该模型均标记为“真实验收未通过”，并在 9003 中保持不可启用。该状态表示当前 Key、协议、模型和平台组合不可用，不武断归因于 Key 本身。

## 6. 测试分层

模拟和契约测试继续用于验证错误分类、参数边界、越权、幂等、并发和敏感信息保护，但不得作为模型可用证明，也不得计入真实验收任务数。

模型接入成功只接受上述真实生产任务证据。真实任务失败后先定位产品代码、配置、供应商响应类别或 Key 权限，不得用 Mock 结果替代、不得把绿色占位图当成供应商结果、不得修改报告为通过。

## 7. 交付与恢复

验收完成后保留 9003 给用户手工复验，并提供管理员与普通测试账号。真实结果保留在隔离目录，用户确认后再决定清理。旧 9003 离线数据在 `/private/tmp` 的备份保持可恢复。

若真实渠道失败，服务继续提供已经通过的渠道，失败线路保持禁用并展示明确、脱敏的管理员诊断。不得为了让界面可点而放宽受信 Origin、合同或归属检查。
