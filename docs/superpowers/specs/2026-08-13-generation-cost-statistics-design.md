# 生成费用统计设计

日期：2026-08-13

状态：已获用户书面批准（2026-08-13）

适用仓库：`ai-creation-canvas`

## 1. 目标

为图片和视频生成提供按用户汇总的近似费用统计。管理员维护全站统一的“每秒视频价格”和“每张图片价格”；所有用户查看自己的用量、费用与明细，管理员额外查看全站及每位用户的统计。

费用是内部统计，不是支付、扣费、退款或供应商账单系统。

## 2. 已确认规则

1. 价格按全站统一，不按模型或服务商区分。
2. 仅管理员可以修改价格；普通用户可以查看自己的费用。
3. 任务首次成功时锁定当时单价。之后修改价格不改变历史费用。
4. 当前供应商链路不提供可靠且统一的 token 用量，因此第一版按可验证的媒体数量估算，不伪造 token 数据。
5. 失败任务、尚未完成的任务和同一任务的重复轮询均不产生费用。
6. 历史任务缺少请求时长及价格快照，第一版不猜测补算；它们在统计中不计费。

## 3. 计量与计费

价格以人民币分（整数）存储与传输，界面以人民币元显示，避免浮点误差。

| 任务操作 | 计量来源 | 费用公式 |
| --- | --- | --- |
| `image.generate`、`image.edit` | 每个首次成功任务为 1 张 | `image_count × image_price_fen` |
| `video.generate`、`video.image_to_video` | 提交请求中已验证的 `duration` 整秒数 | `video_seconds × video_price_fen` |

创建任务时，只从已经通过模型参数校验的请求中提取计量值；不保存提示词或完整参数。任务进入 `succeeded` 的原子更新中读取当前价格，写入该任务的计量值、两项价格快照、总费用和计费时间。成功状态已写入费用的任务不可再次计费。

后续适配器若能返回可信的精确 token、图片张数或视频时长，可在任务完成前覆盖对应的预估计量；统计 API 与前端无需改变。

## 4. 数据与接口

SQLite 迁移新增：

- 一个全站计费设置记录：`video_price_fen`、`image_price_fen`、更新时间。
- `canvas_jobs` 的可公开统计字段：视频秒数、图片张数、视频/图片单价快照、费用分、计费时间。

所有金额和计量字段均为非负整数。设置更新必须由已验证的管理员会话、同源 Origin 与 CSRF 校验保护；更新只影响未来首次成功的任务。

新增版本化接口：

- `GET /api/v1/usage`：当前用户的汇总及本人计费任务明细。
- `GET /api/v1/admin/usage`：管理员的全站汇总、按用户汇总及计费任务明细。
- `GET /api/v1/admin/usage/rates`：读取当前统一单价。
- `PUT /api/v1/admin/usage/rates`：管理员以整数“分”更新两项单价。

普通用户请求管理员接口统一返回现有的隐藏式 `404`，不泄露统计资源存在性。用户明细只返回本人可见的任务元数据、计量、费用和时间，不返回提示词、服务密钥、上游 URL 或原始提供方响应。

## 5. 页面与权限

新增“统计”导航页。

- 普通用户看到：成功任务数、图片张数、视频秒数、累计费用，以及自己的计费任务列表。
- 管理员在相同页面看到：全站汇总、每位用户的用量与费用、全部计费任务列表，并在价格设置区域更新两项单价。
- 设置提交期间禁用提交控件；加载或保存失败显示可理解的错误，现有单价不在失败后被乐观替换。

任务中心可以在后续迭代显示单任务费用；第一版以统计页作为唯一费用入口，避免扩大界面修改范围。

## 6. 错误与边界

- 若视频请求没有有效 `duration`，任务可按原有逻辑执行，但不生成计费记录；统计页将其作为未计费任务排除。
- 单价为零合法，费用记为零且仍计入媒体数量。
- 费用统计只针对本仓库成功完成并写入快照的任务，不与 Portal 或供应商账单作对账。
- 不迁移或读取任何生产目录、状态、日志、结果或密钥；验证仅使用临时测试数据目录和测试端口。

## 7. 验收与延后项

最小可运行闭环：管理员设置视频/图片单价；普通用户完成一张图片和一段已知时长的视频；两人都能在权限范围内看到正确累计费用；管理员改价后再完成任务，旧任务费用不变、新任务使用新价格。

L1 重点覆盖：普通用户无法读写全站统计或价格；失败和重复完成回调不重复计费；历史无快照任务不被误算；不同用户明细严格隔离。

延后项：供应商 token 对账、精确多结果计量、退款/冲正流水、CSV 导出、按模型价目表、额度扣减、支付和财务报表。
