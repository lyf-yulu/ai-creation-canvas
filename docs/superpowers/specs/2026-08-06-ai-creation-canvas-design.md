## 1. 目标

“AI 创作画布”是一个独立维护的无限画布应用。它让 Portal 用户在画布上组织提示词、参考素材、图像和视频生成任务，并把结果直接回填为可继续编排的画布节点。

产品采用两套已经存在的成熟基础：

1. 前端视觉、画布交互和空间组织能力以 Infinite Canvas 为基础。
2. 登录、身份传递、资产、图像与视频服务接入、任务归属和用量统计以内建 Portal 适配层复用现有 Portal 内核的成熟设计。

新项目拥有独立源码、构建、测试和发布流程。它不被塞回原聚合仓库，也不在运行时从原仓库目录加载代码。隔离验证通过后再创建公开 GitHub 仓库。

## 3. 范围

### 3.1 验证版包含

- Infinite Canvas 页面与基本画布编辑。
- 服务端模型目录与模型能力展示。
- 文本生成图片。
- 参考图片编辑。
- 文本生成视频。
- 图片参考生成视频。
- 人像视频工作流：虚拟人图片上传资产库，取得 `asset_id` 后调用视频生成服务。
- 生成状态追踪和结果节点回填。

- 资产、任务和结果归属验证。
- Portal 用量统计对接。

### 3.2 验证版不包含

- Dreamina 接入。
- 视频或音频作为多模态参考素材。
- 普通用户远程插件。
- 动态下载或执行模型脚本。
- 通用工作流语言或工作流引擎。
- 每个已配置模型的真实付费端到端测试。
- 验证通过前的公开仓库创建或生产切换。

## 4. 总体架构

```text
Portal 用户
   │
   ▼
Portal 登录与薄代理入口
   │  注入经签名的用户身份
   ▼
AI 创作画布 Python 服务（8991 / 测试 8992）
   ├── 静态画布构建产物
   ├── Portal 适配层
   ├── 统一任务协议
   └── 人像视频工作流编排
          │
          ├── 资产库服务
          ├── 图像生成服务 ── 多个图像模型
          ├── 视频生成服务 ── 多个视频模型
          └── Portal 任务归属与用量统计
```

架构边界遵循“画布负责编排和呈现，Portal 内核负责身份与治理，生成服务负责模型调用”。Nano Banana 和 Seedance 只是可选模型或代表性实现，不是画布的一级服务边界。

## 5. 前端与构建

### 5.1 前端来源

前端以固定提交的 Infinite Canvas 源码为基础，保留其画布交互和视觉语言，再加入 AI 创作所需的节点、任务状态、模型能力和结果呈现。产品 UI 可以学习并延续 Infinite Canvas 的布局、缩放、拖拽和节点组织方式，不复制来源不明的第三方素材。

### 5.2 构建与运行

- 开发和发布阶段使用上游要求的构建工具并锁定版本。
- 构建结果为静态 HTML、CSS、JavaScript 和资源文件。
- 生产环境只运行 Python 静态/API 服务，不安装或启动 Node/Bun。
- Python 服务不依赖原聚合仓库的本地路径。
- 未来原 Portal 仅保留薄的 iframe 或反向代理入口；画布项目继续独立发布。

## 6. Portal 内核与适配边界

现有 Portal 的成熟实现作为行为基线，包括：

- PBKDF2 密码验证和服务端会话。
- Portal 代理删除浏览器伪造的身份字段，再注入用户名、用户 ID、角色和带时间戳签名。
- 任务所有者映射。
- 按用户和服务统计用量。
- 任务完成状态回报与去重。
- 工作区隔离和前端对失败响应的显式检查。

新画布通过本仓库内的 Portal 适配层使用这些能力。适配层提供稳定的画布侧接口：

- 获取当前会话。
- 获取模型目录及能力。
- 上传和查询资产。
- 创建任务。
- 查询单个或当前用户任务。
- 读取受保护的结果。
- 查询与核对用量归属。

具体 Portal 路由、签名字段和旧服务参数被封装在适配层中，不散落到画布节点代码。原 Portal 将来改变内部实现时，只需更新适配层和契约测试。

## 7. 模型与能力抽象

画布面向两个生成服务：

### 7.1 图像生成服务

统一支持文本生成图片、参考图片编辑及服务端声明的扩展能力。Nano Banana 是代表模型之一，但画布不假设它始终存在。

### 7.2 视频生成服务

统一支持文本生成视频、图片参考生成视频及服务端声明的扩展能力。Seedance 是代表模型之一，但画布不把 Seedance 字段写入核心任务结构。

模型目录只包含数据，例如模型 ID、显示名、服务类型、可用输入、参数约束和当前可用性。目录不能携带或引用需要浏览器执行的远程代码。画布按能力决定显示哪些控件，服务端再次验证所有参数。

### 7.3 可扩展接口

系统必须为后续模型、节点、资产类型和复合工作流保留明确接口，避免把验证版的五条流程固化为不可扩展结构。

#### 前端节点注册表

每类节点通过注册项声明稳定节点 ID、版本、输入端口、输出端口、配置结构、渲染器和可执行动作。画布核心只管理节点生命周期、连线、选择、布局和持久化，不用散落的 `if/switch` 判断具体模型或业务节点。新增节点时可以添加实现和注册项，而不修改画布存储格式的核心逻辑。

#### 服务端能力目录

模型目录以数据描述服务类型、输入媒体、输出媒体、参数约束和可用状态。前端根据能力生成或启用控件，不根据 Nano Banana、Seedance 等名称推断功能。新增模型只需要生成服务适配器和目录记录；通用任务协议保持不变。

#### Portal 端口接口

Portal 适配层分别定义身份、模型目录、资产、任务、结果和用量端口。这里的“端口”是程序内部的稳定接口，不是网络端口号。原 Portal 的具体路由、请求字段、签名方式和返回结构只存在于适配器实现中，画布核心依赖统一领域对象。

#### 工作流编排接口

工作流模块通过标准步骤组合资产上传、资产状态等待、任务提交、任务等待和结果回填。人像视频是第一个复合工作流，但不进入通用任务状态机的硬编码分支。后续增加多步图像处理或其他媒体流程时，复用相同步骤接口。

#### 版本与兼容

- 画布 API 使用明确版本，例如 `/api/v1`。
- 节点数据和任务请求携带结构版本，迁移函数集中管理旧数据升级。
- 新增可选字段保持向后兼容；旧客户端安全忽略未知字段和未知能力。
- 稳定 ID 不使用显示名称，模型改名不破坏历史画布。
- 扩展失败不能影响已注册的其他模型、节点或工作流。

这些扩展点只允许仓库内受审阅和测试的实现注册。它们不开放普通用户远程插件，也不允许模型目录携带可执行代码。验证可扩展性的最低标准是：加入一个测试模型适配器和一个测试节点时，只新增实现与注册，不修改核心身份、任务、用量和画布存储模块。

## 8. 数据流

### 8.1 通用生成

1. 浏览器从画布 Python 服务获取当前 Portal 用户和模型目录。
2. 用户在画布节点中选择模型、输入提示词和参数。
3. 参考图片先上传资产库并获得归属于当前用户的 `asset_id`。
4. 浏览器提交统一任务请求，不提交可信用户 ID 或后端地址。
5. Python 服务从已验证会话取得用户身份，生成画布任务 ID 和幂等键。
6. Portal 适配层把统一请求转换为图像或视频服务的实际协议。
7. 生成服务创建上游任务，Portal 记录任务所有者并负责用量统计。
8. 浏览器用画布任务 ID 查询状态。
9. 成功后，服务返回经过权限校验的媒体引用，浏览器创建图片或视频结果节点。

### 8.2 人像视频工作流

人像功能是画布侧专用视频编排，不是第三个生成服务：

1. 用户生成、选择或上传虚拟人图片。
2. 画布通过 Portal 适配层将图片上传资产库。
3. 资产库完成处理并返回当前用户拥有的 `asset_id`。
4. 画布将该 `asset_id` 作为参考输入调用通用视频生成服务。
5. 视频服务选择 Seedance 或其他兼容模型执行任务。
6. 视频结果按统一任务协议回填画布。

流程使用资产库确认的资产类型和归属，不由浏览器伪造真人或虚拟人字段。真实人物素材仍遵守视频服务和具体模型规则。

## 9. 状态与持久化

统一任务状态为：

```text
uploading → submitting → queued → running → succeeded | failed
```

- 画布本地数据按“环境 + Portal 用户 ID”建立浏览器存储命名空间。
- 用户退出或切换账号时关闭当前存储上下文并清除内存态，不擅自删除该用户已保存的画布。
- 画布服务只保存任务映射和恢复查询所需的最小元数据，不维护第二套计费账本。
- 图像、视频服务和 Portal 用量统计仍是任务执行及费用的权威来源。
- 刷新或断网恢复后查询原任务，不重新提交。
- 结果过期时保留节点布局、输入和任务来源，明确显示结果已过期。

## 10. 安全设计

### 10.1 信任边界

- 浏览器输入不可信，服务端忽略浏览器自报的用户、角色和任务所有者。
- Portal 是登录身份的权威来源。
- Portal 代理清除外部身份头后注入签名身份；画布服务验证签名和时间窗口。
- 生产用户通过 Portal 同源入口访问画布，直接后端端口不是面向普通用户的入口。
- iframe 和跨域消息只接受配置中的 Portal 来源。

### 10.2 密钥与配置

- 模型密钥继续只由图像和视频生成服务持有。
- 画布仓库、Python 服务、浏览器存储和浏览器响应均不保存真实模型密钥。
- 后端服务地址来自服务端白名单，浏览器不能指定任意目标。
- 普通用户不能启用远程插件或动态模型脚本。

### 10.3 资产与文件

- 上传检查请求大小、真实文件类型、支持格式和安全文件名。
- 资产、结果和下载都检查当前用户归属。
- 服务端拒绝路径越界。
- 普通用户不能要求服务端抓取任意 URL。
- 日志只记录必要的请求 ID、内部用户标识、模型 ID、状态和耗时；不记录密钥、完整敏感输入或长期结果地址。

### 10.4 仓库隔离

密钥、状态、输出、归档、上传、日志、浏览器测试数据、真实请求记录和证书均被 Git 忽略。公开仓库创建前执行一次提交内容和历史扫描。

## 11. 错误与重试

统一错误至少包含：

- `AUTH_REQUIRED`
- `FORBIDDEN`
- `ASSET_INVALID`
- `MODEL_UNAVAILABLE`
- `REQUEST_REJECTED`
- `RATE_LIMITED`
- `UPSTREAM_TIMEOUT`
- `TASK_FAILED`
- `RESULT_EXPIRED`
- `INTERNAL_ERROR`

错误响应包含稳定代码、用户提示、是否可重试、请求 ID 和失败阶段，不暴露堆栈、密钥或原始上游响应。

任务提交使用幂等键。如果上游已接收任务但响应丢失，服务端先查询原任务，不直接重复创建。系统不自动切换模型，因为模型价格、效果和规则不同。人像流程分别呈现资产失败和视频失败；资产成功但视频失败时允许复用当前用户拥有的 `asset_id`。

失败节点保留提示词、参数、参考资产和请求 ID。可恢复错误提供继续查询或重新提交，不可恢复错误明确提示登录、输入或模型问题。

## 12. 测试与验收

### 12.1 测试层次

1. 单元测试：节点结果回填、状态转换、存储命名空间和人像步骤编排。
2. 适配器契约测试：使用模拟 Portal、资产、图像和视频服务验证接口。
3. 隔离集成测试：连接全部测试端口和测试数据目录。
4. 浏览器验收：验证实际交互、刷新恢复、图片预览、视频播放和错误提示。
5. 扩展性测试：注册测试模型、测试节点和测试编排步骤，确认核心模块无需随新增类型修改。

### 12.2 必测流程

- 文本生成图片。
- 参考图片编辑。
- 文本生成视频。
- 图片参考生成视频。
- 虚拟人图片入资产库后生成视频。
- 多模型目录和按能力显示参数。
- 刷新、断网和查询恢复。
- 测试模型和测试节点仅通过注册接入，未知能力不会破坏旧画布。

### 12.3 隔离与安全测试

至少创建两个测试用户，验证浏览器存储、资产、任务、结果和用量相互隔离；验证伪造身份头、越界路径、非法文件、超大上传、任意 URL、错误 CORS 来源和动态脚本均被拒绝。扫描构建产物和 Git 提交，确认不存在密钥及运行数据。

### 12.4 故障测试

覆盖会话过期、模型不可用、请求拒绝、频率限制、响应超时但任务已创建、轮询断网、任务失败、结果过期，以及人像资产成功但视频提交失败。验证幂等键阻止重复任务和重复用量，不允许无授权自动切换模型。

### 12.5 真实调用策略

所有模型都执行能力契约测试；真实隔离冒烟测试只选择代表性图像模型、普通视频模型和人像视频流程，以控制成本。真实测试结果仅保存在测试数据目录，不进入 Git。

## 14. 验收门槛

验证版只有同时满足以下条件才可进入公开仓库和后续集成讨论：

- 五条核心生成流程通过。
- 多模型能力抽象不依赖 Nano Banana 或 Seedance 固定名称。
- 新模型、新节点和新工作流可通过稳定接口与注册表增加，不需要改写核心身份、任务、用量和画布存储逻辑。
- 双用户登录、存储、资产、任务、结果和用量隔离通过。
- 超时重试不重复创建任务或重复统计。
- 浏览器和仓库中没有模型密钥或生产数据。
- Python 可独立运行静态构建产物，生产运行不依赖 Node/Bun。
- 生产目录、端口、进程和 launchd 全程未受影响。
- 用户审核验证报告后明确批准创建公开 GitHub 仓库。

## 15. 后续流程

1. 用户复核并书面批准本设计规格。
2. 编写分步骤实施计划，明确源码导入、Portal 适配、测试夹具和回滚点。
3. 按测试驱动方式在测试端口实现。
4. 完成自审、隔离测试和用户验收。
5. 用户批准后创建公开 GitHub 仓库。

本规格确定系统边界和验收标准。具体文件拆分、接口字段和迁移顺序在实施计划中细化，但不得改变本规格的身份来源、服务抽象、安全边界和生产隔离原则。
