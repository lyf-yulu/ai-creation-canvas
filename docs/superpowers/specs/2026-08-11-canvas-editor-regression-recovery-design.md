# 画布编辑器回归修复设计

日期：2026-08-11

## 目标

修复本地验收中暴露的六项问题：媒体节点高度、跨页面返回当前画布、项目页返回入口、多个提示词与并行任务、成功结果状态和连线、连续背景平移。保持现有图契约、服务端任务归属和用户隔离规则，不重写编辑器。

## 已确认的产品规则

- 一个画布允许多个提示词节点。
- 每个模型节点只能有一条当前有效的提示词输入连接；不同模型可以连接不同提示词。
- 一个画布允许多个模型任务同时处于提交、排队或运行状态，各节点状态互不覆盖。
- 媒体集合节点随内容自然增高；0 至 8 个文件全部展开，超过 8 个后在集合内部滚动。
- 从当前画布进入资产或任务页面后，再点“项目”应回到该登录会话最后编辑的画布。
- 项目页提供明确的“返回项目列表”按钮；该动作与“回到上次画布”入口含义不同。
- 成功任务必须把模型节点切换为完成状态，并自动建立模型输出到每个结果节点的连接。

## 根因与设计

### 媒体节点高度

当前媒体列表使用固定最大高度，节点容器同时应用持久化的最小高度。新实现为媒体节点启用内容驱动高度：前 8 项不滚动，实际 DOM 高度由已有 `ResizeObserver` 提供给端口和连线几何；第 9 项起限制列表高度并滚动。持久化节点文档不因测量结果频繁写入，避免同步噪音。

### 页面导航与返回

`ProductShell` 在组件内存中按当前用户会话记住最后访问的 `/canvas/:id`。项目导航链接动态指向该路径；退出登录或壳层卸载后自然清除，不跨用户持久化。项目页面顶部新增返回项目列表链接，始终指向 `/canvas`。不存在或已删除项目继续沿用现有安全回退。

### 多提示词与并行任务

删除创建入口、右键菜单和画布剪贴板中的全局提示词唯一限制。保留图连接层按目标模型仲裁提示词连接的规则，因此同一模型的第二条提示词连接会显示明确冲突，而不会删除原始边。任务 hook 已采用按 job ID 管理的引用和控制器；新增页面回归测试证明两个模型节点可同时排队、运行和独立完成。

### 成功状态与结果连线

成功回调执行一次原子项目更新：

1. 模型节点写入 `status=success`、`jobStatus=succeeded`，清除重试键；
2. 按服务端有界结果列表补齐结果节点；
3. 为每个结果节点补齐 `model.result -> result.result` 命名端口连接；
4. 以 job ID、结果索引和端点元组去重，使刷新、恢复和重复回调保持幂等。

失败、取消和继续轮询仍各自保留现有语义，不把一个模型节点的状态写到另一个节点。

### 连续画布平移

`InfiniteCanvas` 的窗口级 pointer 监听只依赖稳定生命周期。最新的 `onViewportChange` 和 `onCanvasDeselect` 通过 ref 读取，父组件因保存 viewport 重新渲染时不再触发 effect cleanup。pointer ID、cancel、blur、unmount、RAF 最终刷新和 cursor 恢复规则保持不变。

## 错误处理与安全边界

- 只读模式继续禁止节点创建、连接、任务提交和状态修改。
- 最后画布路径仅存在于当前 React 会话，不进入跨用户浏览器持久化。
- 结果连接只接受当前任务来源模型及标准 result 端口，不放宽插件或媒体伪造边。
- 并行任务继续使用独立幂等键、job ID、所有者校验和轮询控制器。
- 本切片不新增付费调用，也不修改现有 8995/8996 验收实例。

## 测试与验收

- 组件测试：媒体项数量引起高度/滚动策略变化；多提示词创建、复制和粘贴；每模型提示词配额不变。
- 导航测试：画布到资产再点项目返回原画布；返回按钮进入项目列表；用户会话切换不复用旧路径。
- 任务测试：两个模型并行；成功状态不残留排队；结果节点和连接幂等生成；失败/取消无回归。
- 交互测试：多次 pointer move 在父组件重渲染后继续累计平移；pointer cancel、blur 和卸载清理保持正确。
- 浏览器测试：桌面完整路径以及 415px、240px 布局；确认返回按钮、节点自适应和连续平移。
- 最终门禁：前后端全量测试、类型检查、生产构建、Chromium、依赖审计、安全扫描和 diff 检查。

完成后使用新的隔离数据目录和新端口启动验收环境，保留 8995/8996 不变，由用户验收后再进入下一阶段。
